# 汎用マニュアル v30 ＋ 発動・検証・改善の仕組み

AIエージェント（Claude）のセッションに対する運用マニュアルを、**書いて終わりにせず、実際に発動し、発動したかを測り、測った結果で改善する**ための一式。

## いま何が入っているか

```
dist/                    ← 配布物（これを各所に貼る）
  L0_core_card_v30.md      コアカード（152行）★常時コンテキストに載せる中核
  L0_core_card_mini_v30.md 短縮版（79行）設定欄の文字数上限で全文が入らない場合の代替
  L1_manual_v30.md         本編（全条文・無省略・124条項）
  L2_records_v30.md        失敗記録（29件）・附則・付録
  manual_v30_all_in_one.md すでに開いているセッションに添付する1ファイル（L0+L1+L2）
  handover_template_v30.md 引き継ぎのテンプレート（記録が残らない [Chat]/[Cowork] 用）
  DISTRIBUTION.md          6箇所への配布手順
.claude/                 ← L3 フック層（Claude Code のみ・機械的強制）
```

## 3分でわかる要点

1. **長さが最大の敵だった。** 公式仕様は「指示ファイルは200行未満を目標、長いほど遵守率が下がる」。v15 は50,647文字あった。
   → **削除せず階層化した。** 常時載る L0（124行）／無省略の L1／記録の L2。**条項は1つも消していない**（120→124へ増えている）。
2. **守ったかどうかを誰も測れなかった。** §0-1 が実況を禁じた結果、痕跡が残らず、§0-12 は測定を諦めていた。
   → **出力契約**（§0-15）を新設。実況ではなく「ユーザーが次の行動を取るために必要な成果」だけを必須にした。**これで初めて機械採点できる。**
3. **強制力の源泉が結局モデル自身だった。** §0-10⑧ もそれを認めていた。
   → **フック層**（L3）を追加。Claude Code では**モデルの判断と無関係に**関門が毎ターン注入され、違反が差し戻される。
4. **作業が途中で止まり、劣化してから慌てて移っていた。**
   → **やり切る義務**（中断してよいのは質問・承認待ち・エラー・危険の4つだけ）と、**劣化の予兆の自動検出**（負荷スコア）を入れた。
   引き継ぎファイルは**必須10章**を定義し、記入漏れを機械で検査する。
5. **説明が専門用語だらけで伝わらなかった。**
   → 初心者基準（§2-13）の適用範囲を「操作を求めるとき」から**説明・報告の全場面**へ広げ、専門用語は初出に1行の意味を書くことを必須にした。
6. **セッションが今日の日付を正確に知らなかった。**
   → 「今日」「現在」「最新」を**現在日時に依存する事実主張**と定義し、毎ターン実測した日時を自動注入するようにした。
7. **自作のテストを自分で採点していた。** §0-12 自身が「実運用の遵守を証明しない」と認めていた。
   → **ChatGPT を5つの役割で組み込んだ。** 中でも**盲検採点**（マニュアルを見せずに採点させる）が中核。
8. **引き継ぎが「記憶から書き写す作業」だった。**（v22 で作り替えた。以後 v30 まで改良を重ねている）
   書き写しは、①手間がかかる ②**劣化したセッションほど精度が落ちる**（最も書き写しが下手な状態で書き写させていた）
   ③要約で原文が失われ、**何が失われたか受け取った側から見えない**——という欠陥を同時に持つ。
   → **記録から生成し、届いたことを機械で照合する**方式へ変えた。
   `[Code]` は会話の全記録を持っているので、`tools/make_handover.py --auto` が
   **依頼の原文・実行したコマンド・触ったファイル・失敗・未完了を要約せずに**書き出す。
   **機械に書けないのは「なぜそう決めたか」＝理由だけ**で、そこには `【要記入】` が置かれ、埋まるまで検査が通らない。
   受け取る側は `--receipt` で件数と指紋（sha256）を照合する。
   **「ちゃんと理解できていますか」という確認の往復をやめる**——確率的な応答への口頭確認は保証にならないが、
   **届いたかどうかは機械で確かめられる**。確かめる対象を「理解」から「到達」へ移した。

## 配布（一度きり。以後は貼り直し不要）

**`dist/bootloader.md`（54行）を2箇所に貼るだけ。** 中身は固定URLから取得されるため、**版を上げても貼り直す必要がありません。**

1. **claude.ai → 設定 →「Instructions for Claude」**
2. **Cowork → 設定 → Cowork →「Global instructions」**

- **進行中のセッション**：`[Code]` は**完全自動**（非同期フックが版を照合し、更新があれば次のターンで新しいコアカードを流し込みます）。`[Chat]`／`[Cowork]` はブートローダーの照合規則により自動で追随します。手動で切り替えたいときだけ **「マニュアル更新」** と打ってください。
- **Claude Code**：`python3 tools/install.py` を一度実行すれば、以後は SessionStart フックが自動で `git pull` して最新化します。**操作は不要。**

固定URL（版番号を含まないため、URLが変わりません）
- コアカード：`latest/L0_core_card.md`
- 全部入り：`latest/manual_all_in_one.md`
- 版の確認：`latest/latest.json`

## 全文を直接貼る方式（ブートローダーが使えない場合）

```bash
python3 tools/install.py --dry-run   # 何が起きるか確認する（何も書き換えない）
python3 tools/install.py             # Claude Code の全プロジェクト＋Cowork デスクトップに導入
```

残るのは**2箇所への貼り付けだけ**です。

1. **claude.ai → 設定 →「Claudeへの指示」** に `dist/L0_core_card_v30.md` の全文を貼る → **すべての会話・すべてのプロジェクト**に効く
2. **Cowork → 設定 → Cowork →「グローバル指示」** に同じ全文を貼る → **すべての Cowork セッション**に効く

文字数の上限で入らない場合は `dist/L0_core_card_mini_v30.md`（4,136字）を使う。
詳細は `dist/DISTRIBUTION.md`。

## セッションを移るとき（引き継ぎ）

**セッションが重くなってきたら、引き継ぎは1コマンドで作れる。** 手で書き写さない。

```bash
# ① 作る（[Code]。会話の原文・コマンド・ファイル・失敗・未完了が要約されずに入る）
python3 tools/make_handover.py --auto handover/myproject_handover_20260901_v1.md

# ② 【要記入】＝「なぜそう決めたか」だけを埋めてから、検査を通す
python3 tools/make_handover.py --check handover/myproject_handover_20260901_v1.md

# ③ 新しいセッションを開く。handover/ に置いてあれば受領確認は自動で走る
#    手で確かめるとき：
python3 tools/make_handover.py --receipt handover/myproject_handover_20260901_v1.md
```

**なぜ「理由」だけが手作業として残るのか**：会話の記録には「何をしたか」は残るが、**「なぜそうしたか」は残らない**。
そこだけは、記憶があるうちに書くしかない。逆に言えば、**それ以外はすべて機械が写せる。**

**受領確認が一致すれば、冒頭の「ちゃんと理解できていますか」という確認作業は不要である。**
確率的な応答に対する口頭確認は保証にならない（「はい、理解しました」は証拠ではない）。
一方、**届いたかどうかは機械で確かめられる。** 確かめる対象を「理解」から「到達」へ移している。

**`[Chat]` `[Cowork]` には会話の記録が無いため、自動生成できない。**
その環境では `dist/handover_template_v30.md` を使い、**節目ごとに同じファイルを作り直す**（§0-5）。
一度に全部を思い出そうとしないことが、精度と負担の両方に効く。

- 記入済みの実例：`docs/examples/handover_20260828_v1_example.md`
- `handover/*.md` は git の追跡対象外（会話の原文を含むため）。共有するときだけ中身を確認して `git add -f`。

## 検証結果（同梱スクリプトで再現できる数値のみ）

| | v13 | v15 | **v16** |
|---|---|---|---|
| 条項総数 | 118 | 120 | **124** |
| 関門・自動発動表からの到達率 | 41% | 98% | **100%** |
| 孤立条項 | 69 | 2 | **0** |
| 失敗記録の捕捉率 | 14/14 | 14/15 | **15/15** |
| 失敗記録の件数 | 14 | 15 | **29** |
| コアカードの行数 | （分離なし） | （分離なし） | **144行**（上限200行） |
| 遵守度の測定手段 | 無し | 無し | **フックによる全ターン記録＋盲検採点** |
| 機械的強制 | 無し | 無し | **6種（`[Code]`）** |
| 自動テスト | 無し | 無し | **123件（フック53・スクリプト70）** |

**v15 の改訂履歴が掲げた「到達率100%・捕捉率15/15」は、独立の再実行で再現できなかった**（98%・14/15）。
判定基準が本文に無く第三者が再現できないことが原因であり、v16 では判定基準をコードとして公開している（`tools/audit_activation.py`）。

## この仕組みが保証しないこと

- **過去のセッションへの遡及反映はできない。** 原理的に不可能である。
- **フック層は Claude Code でしか動かない。** `[Chat]` `[Cowork]` は自己検査に留まる。
- **出力契約が測るのは形式であって、内容の正しさではない。** 内容は盲検採点で測る。両方を見ること。
- **最終的な安全網はユーザーによる裏取りである。** 本マニュアルはそれを不要にするものではなく、**探さなくても分かる形で常に差し出す**ためのものである。

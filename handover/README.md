# `handover/` ＝ 引き継ぎの受け口（`[Code]` 側）

ここに引き継ぎファイル（`*.md`）を置くと、**次のセッションが開始した時点で自動的に受領確認が行われる**。
ユーザーが「ちゃんと引き継げていますか」と質問する必要はない（L1 §10-5）。

---

## `[Code]` での3ステップ

1. **作る**（会話の記録から。要約されない）

   ```
   python3 tools/make_handover.py --auto handover/<案件名>_handover_latest.md
   ```

   自動で入る：**①依頼の原文 ④発行したファイル ⑤調整の経緯 ⑥失敗 ⑦未完了 ⑩使用したコマンド**
   残る `【要記入】`：**②決定の理由 ③却下した案 ⑧次の一手 ⑨前提条件**
   ——**「何をしたか」は記録に残るが、「なぜそうしたか」は残らない。** そこだけは自分で書く。

2. **封をし直す。** 理由を書き足すと、生成時に確定させた指紋（＝1文字でも変われば値が変わる短い符号）が外れる。
   **これは正常である。** 書き終えたことを宣言し、その時点の本文で封をし直す。

   ```
   python3 tools/make_handover.py --seal handover/<案件名>_handover_latest.md
   ```

3. **検査を通す**（`【要記入】` が1つでも残っていれば不合格）

   ```
   python3 tools/make_handover.py --check handover/<案件名>_handover_latest.md
   ```

4. **次のセッションを開く。** 受領確認は自動で走る。手で確かめるときは：

   ```
   python3 tools/make_handover.py --receipt handover/<案件名>_handover_latest.md
   ```

**節目ごとに、同じファイル名で上書きし直す。** 劣化してから作らない（§0-5）。

## 枝分かれ（1つの作業を2つ以上のセッションで進めるとき）

**枝の名前を付けないと、あとから保存したほうが先の枝の引き継ぎを消します。**
消えたことは受領の照合では検出できません（届いたファイルが壊れていないことしか見ないため）。

各セッションで、枝の名前を**一度だけ**決めます（ユーザーに一つだけ質問して決める。勝手に付けない）。

```
python3 tools/make_handover.py --auto handover/<案件名>_handover_latest.md \
        --lane <枝の名前> --parent <分岐元のファイル名>
```

ファイル名は自動で `<案件名>.<枝名>_handover_latest.md` になります。
**枝の名前が決まるまでは保存しません。** 別のセッションが書いた引き継ぎを枝名なしで
上書きしようとすると、**機械的に止まります**。

枝を1本に戻すとき（合流）：

```
python3 tools/make_handover.py --merge handover/<案件名>_merged.md \
        --from handover/<案件名>.<枝1>_handover_latest.md handover/<案件名>.<枝2>_handover_latest.md
```

**要約しません。** 各枝の全文をそのまま連ねます。
**どちらの枝が正しかったかは、ここでは決めません。** 矛盾があれば、それ自体が引き継ぐべき情報です。
**枝の原本は消さないでください。** 合流後も、細部は原本にしかありません。

## 全環境（`[Chat]` `[Cowork]`）と共有するには

`[Code]` の `handover/` はこのマシンの中にしかない。**チャットや Cowork からは見えない。**
全環境で共有するには、**クラウドドライブの `claude_handover/` フォルダ**へ同じファイルを置く（L1 §10-5 受け口）。

- **置く**：ドライブのコネクタで、`claude_handover/` に `<案件名>_handover_latest.md` として保存する。
  形式は `text/markdown`、**Google 形式への変換は無効にする**（変換すると書式が壊れ、指紋が合わなくなる）。
- **読む**：**必ず「生のまま取得」する。** 「自然言語表現として読む」経路は、
  **記号を `\` で退避し、連続する空白を詰める**（2026-09-01 実測）。
  その場合でも受領確認は②「切れて届いた形跡は無い」と判定するが、原文の細部は原本と異なる。
- **日付版も残す**：`<案件名>_handover_20260901_v1.md`。固定名は「探さなくてよい」ため、日付版は「戻れる」ため。

## 注意

- ここに置いたファイルは **git の追跡対象外**である（`.gitignore`）。会話の原文がそのまま入るため、
  公開リポジトリへ載せない。**共有したいときは、中身を確認したうえで明示的に `git add -f` する。**
- 複数ある場合は**最も新しいもの**が受領される。
- 引き継ぎファイル以外の `.md`（この README を含む）は受領対象にならない。判定は「第1章の見出しを持つか」で行う。
- **「セッションが終わる瞬間」を検知する仕組みは、どの環境にも無い。**
  したがって終了時の自動保存は作れない。**節目ごとの上書きがその代わりである。**

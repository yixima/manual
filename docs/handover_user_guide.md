# 引き継ぎ：あなたがすること（配布後の運用）

> **結論：ほぼ何もしません。** 残るのは、**最初の1回の準備**と、**新しいセッションでの一言**だけです。
> 以下は 2026-09-01 時点の設計です。

---

## 0. 最初の1回だけ（案件ごとに1回）

| # | すること | なぜ |
|---|---|---|
| 1 | **案件名を決める**（例：`tokyo-proposal`。半角英数とハイフンだけ） | 受け口のファイル名になる。**一度決めたら変えない**——名前が変わると、次のセッションからは存在しないのと同じになる |
| 2 | Google ドライブに **`claude_handover` フォルダ**があることを確認（作成済み） | 全環境が同じ場所を見るため |
| 3 | （チャットでプロジェクトを使う場合）**プロジェクト指示に1行**：「この案件の引き継ぎ名は `tokyo-proposal`」 | これを書くと、**新しい会話で案件名を言う必要がなくなる**（完全自動になる） |

---

## 1. それまで行っていたセッション（移る前）

### あなたがすること：**基本は何もありません。**

セッションが**自分から**、次のタイミングで受け口へ上書き保存します。

- 一区切りついたとき
- 大きな決定をしたとき
- 大きな成果物を出したとき
- 動作が重くなってきたと判定したとき（`[Code]` は自動で数値判定、`[Chat]` `[Cowork]` は目安で判断）

### 確実にしたいときだけ、一言

> **「引き継ぎを更新して」**

**この一言が唯一の保険です。** 理由は正直に書きます——
**「セッションが終わる瞬間」は、どの環境でも検知できません。** 終了時の自動保存は原理的に作れないため、
節目ごとの上書きで代えています。節目かどうかの判断はセッション側が行うので、**確実ではありません。**
移ると決めた時点でこの一言を打てば、その時点までが確実に残ります。

### 保存されるもの

- あなたの発言の**原文**（要約しません）
- セッションの応答のうち、決定と理由を含む部分の**原文**
- 実行したコマンド・触ったファイル・失敗・未完了
- そして **「なぜそう決めたか」**——これだけは機械に書けないので、セッションが書きます

---

## 2. 新しいセッション（移った後）

### あなたがすること：**最初の一言に案件名を入れるだけ。**

> **「`tokyo-proposal` の続き」**

これだけです。セッションは受け口から該当する引き継ぎを取り、**件数と指紋（＝1文字でも違えば変わる照合値）を照合**して、
その結果を報告してから作業に入ります。

**プロジェクト指示に案件名を書いてある場合（準備3をやった場合）は、この一言も不要です。**
`[Code]` も不要です（作業フォルダの名前で判別します）。

### あなたがしなくてよくなったこと

| これまで | これから |
|---|---|
| 引き継ぎファイルを作れと指示する | 不要（節目ごとに自動） |
| 引き継ぎファイルをダウンロードする | 不要（受け口に置かれる） |
| 新しいセッションに貼り付ける | 不要（自分で取りに行く） |
| 「ちゃんと理解できてる？」と確認する | **不要**（件数と指紋の照合が報告される） |

**最後の1つが、いちばん大きな変化です。** 口頭で確認しても「はい、理解しました」は証拠になりません。
一方、**届いたかどうかは機械で確かめられます**。確かめる対象を「理解」から「到達」へ移しました。

## 3. 環境別のまとめ

| | 移る前のセッション | 新しいセッション |
|---|---|---|
| **チャット** | 何もしない（自動保存）／確実にしたいなら「引き継ぎを更新して」 | 「〇〇の続き」と案件名を書く（プロジェクト指示に書いてあれば不要） |
| **Cowork** | 同上 | 同上 |
| **Claude Code** | 何もしない | **何もしない**（作業フォルダで判別し、開始時に自動照合） |

## 4. 「自動」はどこまで自動か（隠しません）

| 項目 | 保証されるか |
|---|---|
| 置いたものが1バイトも変わらずに届く | **保証される**（3環境で実測済み） |
| 欠落があれば検出される | **保証される**（件数と指紋の照合） |
| セッションが節目を判断して保存を実行する | **確率的**（だから「引き継ぎを更新して」の一言が保険） |
| セッションが終わる瞬間に自動保存する | **できない**（原理的に不可能） |
| 過去のセッションへ遡って適用する | **できない**（原理的に不可能） |

---

## 5. こういうときは

| 状況 | どうなるか／どうするか |
|---|---|
| 受け口に複数の案件が並んでいる | セッションは**勝手に選びません**。名前と更新日時の一覧を示して1つだけ質問します。案件名を答えてください |
| 受け口に何も無い | 何も言わずに、そのまま新しい作業として始まります |
| 引き継ぎが途中で切れて届いた | 受領確認が「**〇〇が△件不足**」と名指しで報告します。元のファイルを取り直します |
| 書式だけ変わって届いた | 「生成時から変わっているが、切れて届いた形跡は無い」と報告されます。**中身は届いています** |
| 引き継ぎに `【要記入】` が残っている | 「その箇所は引き継がれていない」と報告されます。**渡す前の検査で止まるはず**ですが、止まらなかった場合の最後の網です |
